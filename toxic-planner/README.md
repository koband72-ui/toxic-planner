# Toxic Planner v2

Особистий Telegram-планувальник українською. Кнопки та основні команди працюють без Gemini. ШІ пропонує зміни, але код перевіряє власника, параметри та підтвердження перед записом.

## Що реалізовано

- Задачі, пріоритети, терміни, оцінка тривалості, напрями та прив'язка до цілей.
- Природна мова та голосові до 5 хвилин; пропозиції з підтвердженням, пам'ять останніх 20 реплік.
- Додавання, редагування, перенесення з причиною, завершення, скасування завершення, скасування зі збереженням історії. Списки з пагінацією.
- «Що зараз?», інша задача, маленький крок на 5 хвилин. Рекомендація враховує дедлайн і пріоритет; природною мовою можна описати час та сили.
- Фокус 25/50 хв, продовження на 15 хв, допомога при перешкоді. Задача не завершується автоматично. Фактичний робочий час не обліковується.
- Цілі та запропоновані кроки, звички з частотою 1–7 днів на тиждень, парковка ідей та перетворення на задачі.
- План о 08:00, підсумок о 21:00, недільний звіт о 20:00, вибір 1–3 результатів у понеділок, щомісячний перегляд задач без руху 30 днів. Europe/Kyiv із переходами літнього часу.
- Звіт за чотири тижні: головні результати, виконання початкового плану вчасно, звички, прострочені, додані/скасовані задачі, фокус-сесії, напрями та енергія 1–5.
- Три стилі, тихі години, пауза, добовий ліміт додаткових нагадувань. Базові дайджести мають окремі ключі та не витрачають цей ліміт.

## Важливі визначення звіту

Початковий план — задачі, які існували до понеділка 00:00 і початковий дедлайн яких припадає на цей тиждень. Нові задачі відображаються окремо. Перенесення не змінює початковий дедлайн, скасування не стає виконанням. Знімки кожної зміни дозволяють відновити минулий стан. Поточний тиждень неповний, у неділю о 20:00 також лишається чотири години — звіт явно вказує «станом на зараз».

Звичка — максимум одна відмітка на день, мінімальний обсяг визначає користувач. Пропуски не обнуляють історію. Цільова частота фіксується на початок тижня (або при створенні звички). Енергія не входить до штучного загального рейтингу. Старі імпортовані завершення без дати не приписуються поточному тижню.

## Перед запуском на наявному Render

Це оновлення потребує налаштування інфраструктури ДО злиття в гілку автодеплою. До цього робочий старий сервіс не змінюється.

1. Підключити постійну PostgreSQL-базу та задати `DATABASE_URL`. Не використовувати SQLite на Render Free. Без PostgreSQL запуск на Render навмисно зупиняється.
2. За можливості зберегти копію старого `planner.db` ДО будь-якого перезапуску/деплою. Копію імпортувати командою `python scripts/import_legacy.py /secure/path/planner.db` із цільовим `DATABASE_URL`. Повторний імпорт тієї самої копії не дублює дані. Якщо старий диск уже втрачено, відновити його цим кодом неможливо.
3. У Render Environment встановити `BOT_TOKEN`, `GEMINI_API_KEY`, `DATABASE_URL`, `WEBHOOK_SECRET`, `CRON_SECRET`. `WEBHOOK_BASE_URL` — зовнішній HTTPS URL сервісу; можна використовувати автоматичний `RENDER_EXTERNAL_URL`. Два секрети генерувати незалежно, мінімум 32 символи. Не комітити значення.
4. Поточний build: `pip install -r requirements.txt`; start: `python bot.py`; Python 3.12; health check `/healthz`. Нова версія використовує Telegram webhook, а не polling на Render.
5. Налаштувати зовнішній виклик `POST /cron/tick` з заголовком `Authorization: Bearer <CRON_SECRET>`. У репозиторії підготовлений GitHub Actions: додати **Actions secrets** `PLANNER_URL` та `CRON_SECRET`; workflow діятиме за розкладом лише після потрапляння в default branch. Значення CRON_SECRET однакове на Render і в Actions.
6. Після деплою перевірити `/healthz`, запуск workflow вручну, `/start`, додавання/підтвердження/завершення задачі, голосове, збереження після рестарту, нагадування та логи. Локальні тести не замінюють ці перевірки з живими інтеграціями.

### Обмеження безкоштовного розгортання

Render Free засинає через 15 хв без вхідного трафіку, локальні файли втрачаються при перезапуску/засинанні, пробудження може зайняти близько хвилини. Безкоштовна Render Postgres закінчується через 30 днів: це не постійне безкоштовне сховище. Потрібна окрема довготривала база або свідомий вибір платного варіанта. Платні ресурси автоматично не створюються.

Зовнішній виклик будить сервіс, а база зберігає вже надіслані нагадування. GitHub Actions раз на 5 хв — best effort: запуски можуть затримуватись/пропускатись; у неактивному публічному репозиторії scheduled workflows можуть вимкнутись. **Точне доставлення о 08:00 і точний фокус-таймер на Free не гарантовані.** Для точного розкладу потрібні відповідний scheduler і постійно працюючий сервіс. Пропущені ранкові/вечірні дайджести надолужуються лише в межах відповідного дня/вікна, старі не розсилаються пачкою.

Доставка має збережену 5-хвилинну оренду й повтор після помилки. Telegram не дає idempotency key для sendMessage: збій між прийняттям повідомлення Telegram та записом результату в БД може дати дубль. Звичайні повторні tick не дублюють повідомлення. Повторні текстові Telegram updates мають журнал останніх 2000 мутацій на користувача; це обмежений захист, а не безмежна гарантія exactly-once.

Токен прибрано з нового коду. Попередні Git-коміти можуть досі містити старий токен; видалення рядка не відкликає його.

## Локальна перевірка

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
```

Локально без `RENDER` і без `DATABASE_URL` використовується `planner-v2.db`. Без зовнішнього URL бот використовує polling. Для локальних тестів жодні реальні секрети не потрібні.

Дані зберігаються транзакційно по користувачах, PostgreSQL використовує блокування рядка. Поточна модель документа розрахована на особистого бота, не масовий сервіс: історія росте, для великого навантаження потрібні нормалізовані таблиці/архівація.

Офіційні довідки: [Render Free](https://render.com/docs/free), [aiogram webhooks](https://docs.aiogram.dev/en/latest/dispatcher/webhook.html), [Google Gen AI SDK](https://googleapis.github.io/python-genai/), [GitHub scheduled events](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).
